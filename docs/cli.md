# CLIと起動方法

## 状態

V0.1方針。Webサーバーの起動入口、仕様の直接読込、`--specs`の入力規則は確定済みである。DBパスとポートの指定方法などの詳細は未決である。

## 目的

CLIは製品の主画面ではなく、Webサーバーの起動や管理操作の入口として扱う。テストの閲覧と結果入力はブラウザを主とする。

## 起動方法

```text
testman serve --specs ./testspecs
```

localhostでWeb画面を提供する。画面表示時には仕様ファイルを原本として直接読み込み、SQLiteへ仕様本文をimportしない。

`--specs`には、`.md`ファイルまたはディレクトリの絶対パス・相対パスを指定できる。相対パスは起動時のカレントディレクトリを基準とする。ファイル指定時はその1ファイルだけを読み、ディレクトリ指定時は配下の`.md`を再帰的に読む。シンボリックリンクおよびWindowsのジャンクションは探索しない。

指定パスが存在しない場合、または指定ディレクトリ配下に対象`.md`が1件もない場合は、ターミナルへエラーを表示してWebサーバーを起動しない。対象ファイルを確定した後に個別ファイルの読込・文字コード・解析エラーが発生した場合はサーバーを起動し、Web画面上部へ診断を表示する。正常に解析できたファイルとtitleは表示を継続する。

### 仕様ディレクトリを監視する案

起動中にファイル変更を検出して再読込する。利便性は高いが、再読込失敗時の状態や履歴との対応が複雑になるため、V0.1では必須としない。

## V0.1方針

V0.1では `serve` でlocalhostにWeb画面を提供し、画面表示時に現在の仕様ファイルを直接読み込む。仕様本文をSQLiteへimportするコマンドは設けない。
