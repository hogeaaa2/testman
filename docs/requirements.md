# 要求仕様

## 状態

V0.1要求。確定済みの要求を記載する。追加確認が必要な事項は [未決事項](open-questions.md) で管理する。

## 目的

`testman`は、ファイルとして管理されるテスト仕様をブラウザで閲覧し、テスト結果を入力・蓄積・参照できるようにする。

同時に、複数のAIエージェントがArchitect、Implementer、Reviewerの役割に分かれて協業するための実験用リポジトリとして機能する。

## 確定している要求

### テスト仕様

- テスト仕様はMarkdownまたは同等の人間が編集可能なファイルを入力とする。
- テスト仕様はGitで管理できるものとする。
- リポジトリに動作確認用のサンプル仕様を置いてよい。
- テスト仕様は見出しを持ち、主要部分は表形式になる可能性が高い。
- テスト仕様は、title見出しごとに、詳細な手順や期待結果を確認する前にテストパターンの全体像をレビューできる概要を必ず持つ。
- テスト仕様形式は [test-format.md](test-format.md) に従う。
- 1つの仕様ファイルに複数のTest IDを記載できる。件数は、その仕様に対応するissueのスコープに応じて決まる。
- 1つのTest IDは、1つのテスト意図を表す。
- Expected Resultは原則としてTest IDごとに1つとする。同じテスト意図を保つ範囲では、1つのTest ID内の複数手順に対応する複数の期待内容を記載できる。
- Test IDは仕様ファイル単位で一意とする。同じ仕様ファイル内の最大番号をインクリメントして採番し、削除されたIDや欠番を再利用しない。
- 起動時の仕様パスには、単一のMarkdownファイルまたはディレクトリを指定できる。
- ディレクトリを指定した場合は、配下のサブディレクトリを含めてMarkdownファイルを再帰的に読み込む。ただし、シンボリックリンクおよびWindowsのジャンクションはたどらない。
- 仕様パスには絶対パスまたは相対パスを指定できる。相対パスはtestman起動時のカレントディレクトリを基準とする。

### Webアプリケーション

- 利用者はブラウザでテスト仕様を読みやすい形で閲覧できる。
- 利用者は、テストパターンをレビューする表示と、詳細を参照して検証を実施する表示を切り替えられる。
- 利用者はブラウザからテスト結果を入力できる。
- 利用者は過去のテスト結果を確認できる。
- 初期版は小規模なWebサーバー型アプリケーションとする。
- V0.1のWebサーバーは同一PCからだけ利用し、localhostで待ち受ける。

### テスト結果

- テスト結果はSQLiteへ保存する。
- SQLiteの実データベースファイルはGit管理しない。
- schemaとmigrationはGit管理する。
- 同じテストに対して複数回の結果を保存し、過去の履歴を上書きしない。
- V0.1で最低限Pass、Fail、任意コメント、実施日時、検証実施者名を扱う。
- 各実施結果には、実施時点のテスト仕様を追跡するため、その仕様が含まれるGit commit SHAを保存する。
- 検証に使用するテスト仕様はGitへコミット済みであることを運用上の前提とする。
- 過去の仕様本文はGitで確認し、testmanのWeb UIでは復元・表示しない。
- 仕様からTest IDや仕様ファイルが削除されても、保存済みの実施結果は削除しない。

### 開発プロセス

- 実装前にユーザーと仕様をすり合わせる。
- 仕様不足をImplementerが推測で補わない。
- 仕様、実装、レビューの責務を分離する。
- 役割ごとの作業手順をSkillとして管理する。

## V0.1のスコープ

- テスト仕様ソースを読み込む。
- テストケース一覧をブラウザに表示する。
- テストケース詳細をブラウザに表示する。
- PassまたはFailとコメントを入力する。
- 結果をSQLiteへ追記する。
- テストケースごとの実施履歴を表示する。

一覧の表示項目や登録前確認など、詳細に残る選択事項は [未決事項](open-questions.md) で管理する。

## V0.1の対象外

- 認証と認可
- 複数ユーザーの同時利用を前提にした機能
- REST APIとフロントエンドの分離
- 外部DBサーバー
- プラグインシステム
- 分散構成
- Web画面からのテスト仕様編集
- 高度なレポート生成

## 品質要求

- テスト仕様の解析エラーを利用者が特定できる形で表示する。
- 不正なHTMLやスクリプトをブラウザで実行させない。
- GitHub Flavored Markdown相当の記法と安全な生HTMLを許可し、危険なHTML、属性、URLを表示前に除去する。
- テスト仕様の変更や再読込によって過去の実施履歴を意図せず失わない。
- ローカルで容易に起動、終了、初期化できる。
- 自動テストで主要な解析、保存、Web操作を確認できる。
