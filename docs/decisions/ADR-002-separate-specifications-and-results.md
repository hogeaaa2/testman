# ADR-002: テスト仕様と実施結果を分離する

- Status: Accepted
- Date: 2026-09-28

## Context

テスト仕様は人間が編集し、Gitで変更履歴を管理したい。実施結果は繰り返し追加され、仕様ファイルへ書き戻す用途には向かない。

## Decision

- テスト仕様はファイルで管理し、Gitへコミットする。
- 実施結果はSQLiteへ追記する。
- Web UIから仕様ファイルを編集しない。
- SQLiteの実データベースファイルはGitへコミットしない。
- DB schemaとmigrationはGitへコミットする。
- サンプルのテスト仕様はGitへコミットしてよい。

## Consequences

- テスト設計の変更は通常のコードレビューと同様に扱える。
- 実施履歴によってリポジトリが頻繁に変更されない。
- 仕様の変更・削除と過去の履歴をどう関連付けるか、追加設計が必要になる。
- DBのバックアップと移行はGitとは別に考える必要がある。
