# ADR-003: テスト仕様形式

- Status: Accepted
- Date: 2026-09-28
- Updated: 2026-09-29
- Accepted: 2026-09-29

## Context

テスト仕様には見出しと表形式が必要になる可能性が高い。Markdown表、テストごとのMarkdownセクション、構造化データ、HTML tableにはそれぞれ異なる利点と制約がある。

## Decision

正式な形式は `docs/test-format.md` に定義する。

Markdownの見出しを表全体のtitleとし、titleごとにテストパターンの目的と範囲をレビューするためのOverviewを必須とする。Overviewの後には、全行へ適用するPreconditionsとCommon steps、およびテストケース表を置く。表の各行は一意なID、大項目、中項目、小項目、任意の行別Steps、期待結果を持つ。

Common stepsから「行別Stepsに記載があれば、それに従って操作する」と指示でき、同じ表の中に行別Stepsの記載あり・なしを混在できる。Stepsの空セルは許可し、半角ハイフン1文字 (`-`) で行別Stepsがないことを明示してもよい。Common steps内の具体的な参照文言はツールで固定しない。

1つのTest IDは1つのテスト意図を表す。Expected Resultは原則としてIDごとに1つとするが、同じテスト意図の範囲内では、複数手順に対応する複数の期待内容を1つのExpected Resultセルへ記載できる。1つの仕様ファイルにはissueのスコープに応じて複数のTest IDを置ける。

Test IDは `TC-#` 形式とし、仕様ファイル単位で一意とする。同じ仕様ファイル内の最大番号の次を採番し、削除済みIDや欠番を再利用しない。

大項目、中項目、小項目に特に記載する内容がない場合も半角ハイフン1文字 (`-`) で示す。

分類値は通常のMarkdown表で各行に記載し、testmanのWeb表示時に連続する同一値をセル結合する。Markdown入力にはセル結合用の拡張記号やHTMLを導入しない。階層関係を保つため、下位分類の結合は同じ上位分類の範囲内に限定する。`-` は分類値ではなく「記載なし」を示すため、連続していても結合しない。

GitHub Flavored Markdown相当の記法と生HTMLを入力として許可する。Markdownから生成したHTMLと生HTMLは許可リスト方式でサニタイズし、危険な要素、属性、URLを除去する。

ファイル先頭には `Testman-Format-Version: 1` を置く。V0.1では値を表示するが、解析処理の分岐には使わない。

構造エラーは画面上部へ診断し、正常に解析できるtitleは表示を継続する。解析できないtitleは理由を表示し、重複IDなど安全に識別できない行は結果登録を無効化する。

## Decision Criteria

- 実際のテスト仕様を無理なく記述できる。
- Git上のレビューと差分確認がしやすい。
- C#で曖昧さなく検証できる。
- 安全にWeb表示できる。
- 将来の変更時に互換性を管理できる。

## Rationale

実際の利用に近いサンプルで候補を比較した結果、見出し、共通記述、表を組み合わせる案が、概要から詳細への段階的レビューとGit上の一覧性を最も両立した。

生HTMLを無加工で表示せず、必要な表現を許可しながら危険な内容を除去することで、localhost限定でもブラウザ内の不正なコード実行を防ぐ。

## Consequences

- パーサーはtitle単位の診断と部分成功を扱う必要がある。
- 表の列名、列順、ID形式、必須セクションを検証する必要がある。
- GFM変換後のHTMLと生HTMLの両方へサニタイズを適用する必要がある。
- 互換性を壊す形式変更ではバージョンと移行方針を新しいADRで決定する。
