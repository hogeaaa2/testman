# Web UI 方針

## 状態

V0.1方針。基本構成、一覧の表示項目、結果入力と登録時の確認方法を定義する。新たな不足や矛盾は [未決事項](open-questions.md) で管理する。

## 基本方針

- **REQ-0051**: ASP.NET Core Razor PagesでHTMLを生成するシンプルなサーバーサイドWeb UIとする。
- **REQ-0052**: テスト実施者が仕様を読みながら結果を入力しやすいことを優先する。
- **REQ-0053**: 詳細な実施内容へ入る前に、テストパターンの概要をレビューできるようにする。
- **REQ-0054**: V0.1ではWeb画面から仕様ファイルを編集しない。
- **REQ-0055**: 画面表示時には、現在のテスト仕様ファイルを原本として直接読み込む。SQLiteへimportした仕様本文を表示元にしない。
- **REQ-0056**: JavaScriptへの依存は、操作性に必要な範囲へ抑える。

## 画面構成

### 表示モード

**REQ-0057**: 同じテスト仕様について、次の表示を切り替えられるようにする。

- **REQ-0058**: テストパターン表示: title、概要、大項目、中項目、小項目を表示し、「どのようなテストをするか」をレビューする。Test IDとPreconditionsは表示しない。
- **REQ-0059**: 検証実施表示: Test ID、前提条件、共通Steps、行別Steps、Expected Result、結果入力を表示し、実際の検証に使用する。

**REQ-0060**: 表示モードの切り替えは仕様データを変更せず、同じテストケースを異なる詳細度で表示する。

### テスト一覧

- **REQ-0061**: Test ID
- **REQ-0062**: タイトル
- **REQ-0063**: 所属する仕様ファイルまたはグループ
- **REQ-0064**: 最新結果
- **REQ-0065**: 最終実施日時

**REQ-0066**: Test listでは仕様Markdownファイルのパスに続けて、そのファイルを最後に変更したGit commit SHAを丸括弧で表示する。この値は結果登録時に`specification_revision`へ保存するSHAと同じ意味を持つ。

**REQ-0067**: フォルダを仕様パスに指定した場合は、仕様ファイルごとに次の現在状況を表示する。

- **REQ-0068**: 現在の有効かつ一意なTest IDの総数
- **REQ-0069**: Pass、Fail、Blocked、N/Aの件数
- **REQ-0070**: 実施履歴が1件もないTest IDの件数を表す未テスト数

**REQ-0071**: 各Test IDの区分には、同じGitリポジトリルート、仕様ファイル相対パス、Test IDを持つ実施記録のうち内部IDが最大のものを最新結果として使用する。現在の仕様から削除済みのTest IDは現在状況の集計から除外するが、履歴は削除しない。重複IDや不正な行は診断対象とし、通常の集計には含めない。

### テスト詳細・実施

- **REQ-0072**: Test IDとタイトル
- **REQ-0073**: 前提条件
- **REQ-0074**: 手順
- **REQ-0075**: 期待結果
- **REQ-0076**: 前回結果
- **REQ-0077**: Pass / Fail / Blocked / N/Aの選択
- **REQ-0078**: コメント
- **REQ-0079**: 検証実施者名
- **REQ-0080**: テスト対象名
- **REQ-0081**: 登録操作

**REQ-0082**: 前回結果は、同じGitリポジトリルート、仕様ファイル相対パス、Test IDについて保存された内部IDが最大の実施記録とし、履歴がなければNot Testedと表示する。表ではExpected Result列と結果入力列の間に置く。実施日時はDBへUTCで保存し、画面では実行環境のローカル時刻で表示する。

#### Previous result列の表示

**REQ-0083**: 列内の要約は最新結果のバッジのみとし、履歴がなければNot Testedのバッジを表示する。履歴がある場合はHistoryの開閉を併記する。実施日時、検証実施者名、テスト対象名、コメントはHistoryを開いたときに表示し、列内の要約には並べない。

#### Verification表の列幅

**REQ-0084**: テストケース表の列幅はtitleや行の文章量によって変動させず、次の割合に固定する。Test listやテストパターン表示の表には適用しない。

| Test ID | Steps | Expected result | Previous result | Result input | Optional comment |
|---:|---:|---:|---:|---:|---:|
| 6% | 28% | 26% | 12% | 12% | 16% |

**REQ-0085**: 長い文章やURLはセル内で折り返す。狭い画面では入力欄が使える最小幅を保ち、表全体を横スクロールできるようにする。

**REQ-0086**: 結果入力用コンボボックスの初期値は、前回結果の有無や値にかかわらず空の未選択状態とする。前回結果を入力欄へ自動設定しない。Not Testedはコンボボックスで選択して保存する結果値ではない。

**REQ-0087**: 結果入力は未選択を許可する。登録操作では、結果が選択されたケースだけを新しい実施記録として追記する。登録可能なケースの一部に未選択がある場合は、「すべてのケースに結果が入力されていない」旨を示し、選択済みケースだけを登録するか確認する。すべて未選択の場合は登録せず入力エラーを表示する。すべて選択済みの場合は確認を挟まず登録する。

**REQ-0088**: 同じ画面の複数ケースは1回の操作で一括登録し、保存は1トランザクションで行う。登録成功後は成功を明示し、ブラウザの再送信操作で意図せず同じPOSTを繰り返さない画面遷移とする。

**REQ-0089**: テスト対象名は1回の登録操作に共通する必須入力欄とし、exeのファイル名などを記載できる。検証実施者名と同じく、前後の空白を除去した後に空なら入力エラーを表示して登録を拒否する。

### 実施履歴

- **REQ-0090**: 実施日時
- **REQ-0091**: 結果
- **REQ-0092**: コメント
- **REQ-0093**: 検証実施者名
- **REQ-0094**: テスト対象名

**REQ-0095**: Previous result列内で展開する履歴には、各実施結果のテスト対象名を表示する。仕様MarkdownのGit commit SHAは結果に保存するが、この履歴表示には出さない。過去の仕様本文はGitで確認し、Web UIでは復元表示しない。

## エラー表示

- **REQ-0096**: 仕様ファイルのパス、可能なら行番号、エラー理由を表示する。
- **REQ-0097**: 診断を画面上部へ目立つ形で一覧表示する。
- **REQ-0098**: 正常に解析できたtitleは表示を継続し、解析できないtitleは理由を表示する。
- **REQ-0099**: 重複IDまたは安全に識別できない行は表示してよいが、結果登録を無効化する。
- **REQ-0100**: 利用者の入力エラーとシステム障害を区別する。
- **REQ-0101**: DB保存に失敗した場合、成功したように見せない。
- **REQ-0102**: 内部例外やスタックトレースを通常画面へそのまま表示しない。

## セキュリティ

- **REQ-0103**: GitHub Flavored Markdown相当の記法と生HTMLを入力として許可する。
- **REQ-0104**: Markdownから生成したHTMLと生HTMLは、`docs/test-format.md` の許可リストでサニタイズする。
- **REQ-0105**: `script`、危険な埋め込み要素、イベント属性、危険なURLなど、許可リスト外の内容を除去する。
- REQ-0021 に従い、V0.1の待受アドレスはlocalhostに限定し、同一PCからだけ利用する。
- **REQ-0106**: 外部公開や複数人利用が必要になった場合は、認証、CSRF、権限、TLSを改めて設計する。
