# CLIと起動方法

## 状態

初期案。Webアプリの起動方法と仕様読込方式が決まるまで確定しない。

## 目的

CLIは製品の主画面ではなく、Webサーバーの起動や管理操作の入口として扱う。テストの閲覧と結果入力はブラウザを主とする。

## 候補

### 明示的に起動する案

```text
testman serve --specs ./testspecs
```

起動時に仕様を検証・読込し、localhostでWeb画面を提供する。

### importを分離する案

```text
testman import ./testspecs
testman serve
```

仕様の検証と反映を明示的に分けられるが、利用者が同期操作を忘れる可能性がある。

### 仕様ディレクトリを監視する案

起動中にファイル変更を検出して再読込する。利便性は高いが、再読込失敗時の状態や履歴との対応が複雑になるため、V0.1では必須としない。

## 暫定推奨

V0.1では `serve` の起動時に仕様ファイルを検証・読込する案を第一候補とする。明示的な `import` は、独立させる必要性が確認できた場合に追加する。
