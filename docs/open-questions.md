# 未決事項

この文書は、ユーザーとのすり合わせが必要な事項を管理する。回答を得た項目は、該当仕様またはADRへ反映してからここから除く。

## 優先度A: 実装開始前に必要

1. テスト仕様形式はどの案を採用するか。実際のテストに近いサンプルで比較する必要がある。
2. 期待結果はテスト全体で1つか、各手順に対応させるか、両方を許可するか。
3. 仕様ファイル1つに複数テストを置くか、原則1テスト1ファイルにするか。
4. 仕様ファイルを起動時に直接読むか、SQLiteへimportしたコピーを画面表示に使うか。
5. 仕様変更後も、過去の実施時点の内容を再現できる必要があるか。
6. 仕様から削除されたテストの履歴を、Web画面から引き続き閲覧できるようにするか。
7. Webサーバーの利用範囲は同一PCだけか、LAN内の別端末からもアクセスするか。
8. V0.1で実施者名を入力・保存する必要があるか。

## 優先度B: 縦切り実装前後に決められる

1. 最新結果や最終実施日時を一覧に表示するか。
2. 結果登録前に確認画面を出すか。
3. `Blocked`、`Skipped`、`Not Applicable`などをV0.1で扱うか。
4. 仕様の絞り込み、検索、並び替えの最低要件は何か。
5. Markdown内の画像とリンクを許可するか。
6. DBと仕様ディレクトリの既定パスをどこにするか。
7. 仕様エラーが1件でもあれば全件を拒否するか、正常なものだけ表示するか。

## 将来検討

- テスト実行セッションやリリース単位の集計
- エクスポートとレポート
