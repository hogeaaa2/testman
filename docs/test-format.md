# テスト仕様形式

## 状態

V0.1形式。ADR-003で採用された正式仕様である。

## ファイル構造

- REQ-0001 に従い、UTF-8のMarkdownファイルとする。
- **REQ-0172**: 先頭行は `Testman-Format-Version: 1` とする。
- **REQ-0173**: 形式バージョンは正の整数として画面に表示する。V0.1では値によって解析処理を分岐しない。
- **REQ-0174**: 1ファイルに複数のtitleブロックを置ける。
- **REQ-0175**: titleブロックはレベル1見出し (`#`) で開始する。
- **REQ-0176**: 各titleブロックは、次の要素をこの順で1つずつ持つ。
  1. `## Overview`
  2. `## Preconditions`
  3. `## Common steps`
  4. テストケース表
- **REQ-0177**: titleブロック内の表は1つだけとする。別の表が必要な場合はtitleを分ける。
- **REQ-0178**: Overview、Preconditions、Common stepsは必須であり、空にしない。該当事項がなければ文章で `なし` と記載する。

## 入力ファイルの選択

- **REQ-0179**: 仕様パスには、`.md`拡張子を持つ単一ファイルまたはディレクトリを指定できる。
- **REQ-0180**: 単一ファイルを指定した場合は、そのファイルだけを読み込む。
- **REQ-0181**: ディレクトリを指定した場合は、その配下にある`.md`ファイルをサブディレクトリまで再帰的に読み込む。
- **REQ-0182**: シンボリックリンクおよびWindowsのジャンクションに該当するファイルやディレクトリは読み込まず、リンク先も探索しない。
- **REQ-0183**: 絶対パスと相対パスを許可する。相対パスはtestman起動時のカレントディレクトリを基準に解決する。
- **REQ-0184**: 指定パスが存在しない場合、またはディレクトリ配下に対象`.md`ファイルが1件もない場合は入力対象を確定できないため、Webサーバーを起動しない。
- **REQ-0185**: 対象ファイルを確定した後の読込エラーや解析エラーはファイルごとの診断とし、正常なファイルとtitleの表示を妨げない。

## テストケース表

**REQ-0186**: 列名と列順は次に固定する。

| ID | Major item | Middle item | Minor item | Steps | Expected result |
|---|---|---|---|---|---|

- **REQ-0187**: 表には1行以上のテストケースを記載する。
- **REQ-0188**: ID、Major item、Middle item、Minor item、Expected resultは必須であり、空セルを許可しない。
- **REQ-0189**: Major item、Middle item、Minor itemに記載事項がなければ、半角ハイフン1文字 (`-`) を記載する。
- **REQ-0190**: Stepsは任意であり、空セルを許可する。`-` で「行別Stepsなし」を明示してもよい。空セルと `-` は入力どおり表示する。
- REQ-0008 に従い、Expected resultは原則としてIDごとに1つとする。同じテスト意図の範囲内では、複数手順に対応する複数の期待内容を同じセルへ記載できる。
- **REQ-0191**: セル内で縦棒を文字として使う場合は `\|` と記載する。
- **REQ-0192**: セル内の明示的な改行には、許可HTMLである `<br>` を使用できる。

## Test ID

- **REQ-0193**: Test IDは `TC-#` 形式とする。`#` は1から始まる10進整数であり、先頭ゼロを付けない。例: `TC-1`、`TC-2`。
- **REQ-0194**: Test IDは仕様ファイル単位で一意とする。
- **REQ-0195**: 新規IDは、同じファイルで過去に使用した最大番号の次を採番する。
- REQ-0009 に従い、削除済みIDと欠番は再利用しない。
- **REQ-0196**: IDは「何をテストするか」というテスト意図の同一性を表し、その意図が変わらない限り変更しない。
- **REQ-0197**: ファイル名を変更してもIDを変更しない。
- **REQ-0198**: ケースを別ファイルへ移動する場合は、移動元のIDを削除扱いとし、移動先ファイルで新しいIDを採番する。

## StepsとExpected result

- **REQ-0199**: 1つのIDは1つのテスト意図だけを扱う。
- **REQ-0200**: Common stepsはtitle内の全テストケースへ適用する。
- **REQ-0201**: Common stepsは、任意の位置で行別Stepsを参照できる。参照文言はテスト仕様の記述者に委ねる。
- **REQ-0202**: 行別Stepsの有無や分量だけを理由に、IDを分割または統合しない。
- **REQ-0203**: 複数のExpected resultを記載する場合も、全体として1つのテスト意図を検証する内容に限る。

## MarkdownとHTML

- **REQ-0204**: GitHub Flavored Markdown相当の見出し、段落、強調、取り消し線、リスト、リンク、画像、引用、インラインコード、コードブロック、表、自動リンクを許可する。
- **REQ-0205**: 生HTMLは入力できるが、Web表示前に許可リスト方式でサニタイズする。
- **REQ-0206**: 許可するHTML要素は `h1`、`h2`、`h3`、`h4`、`h5`、`h6`、`p`、`br`、`hr`、`strong`、`em`、`del`、`code`、`pre`、`blockquote`、`ul`、`ol`、`li`、`a`、`img`、`details`、`summary`、`kbd`、`sub`、`sup`、`table`、`thead`、`tbody`、`tr`、`th`、`td` とする。
- **REQ-0207**: `a`では `href` と `title`、`img`では `src`、`alt`、`title`、`width`、`height`、表要素では `colspan` と `rowspan` だけを許可する。
- **REQ-0208**: URLは相対URL、`http`、`https`、`mailto`だけを許可する。画像のURLは相対URL、`http`、`https`だけを許可する。
- **REQ-0209**: `script`、`style`、`iframe`、`object`、`embed`、`form`、`input`、`button`、SVG、イベント属性、`style`属性、`javascript:`など許可外の要素・属性・URLは除去する。
- **REQ-0210**: サニタイズ後のHTMLだけをブラウザへ出力する。

## Web表示

- **REQ-0211**: テストパターン表示ではtitle、Overview、Major item、Middle item、Minor itemを表示し、Test IDとPreconditionsは表示しない。
- **REQ-0212**: 検証実施表示ではTest ID、Preconditions、Common steps、Steps、Expected result、結果入力を表示する。
- **REQ-0213**: 分類列で同じ実値が連続する場合、Web表示では階層境界を守ってセル結合できる。
- **REQ-0214**: `-` は「記載なし」を表す予約値のため、連続していてもセル結合しない。
- REQ-0173 に従い、ファイルの形式バージョンを画面に表示する。

## 診断と部分表示

- **REQ-0215**: 診断には仕様ファイルのパス、可能なら行番号、理由を含め、画面上部へ目立つ形で一覧表示する。
- **REQ-0216**: ファイル内のすべてのtitleを可能な限り解析し、正常なtitleは表示する。
- **REQ-0217**: 必須見出し、必須列、表などが欠落して解析できないtitleは表示せず、その理由を診断する。
- **REQ-0218**: 他のtitleのエラーを理由に、正常なtitleを非表示にしない。
- **REQ-0219**: 重複Test IDは `Duplicated ID detected: TC-1, TC-2` のように一覧表示する。
- **REQ-0220**: 重複IDを持つ行は表示してよいが、対象を一意に識別できないため結果登録を無効化する。
- **REQ-0221**: 不正なID、必須セルの空欄など、結果との対応が安全に確定できない行も結果登録を無効化する。
- **REQ-0222**: Stepsの空セルはエラーにしない。
- **REQ-0223**: 形式バージョン行の欠落または数値以外の値はファイルレベルの診断とする。解析可能なtitleは部分表示してよいが、当該ファイルの結果登録を無効化する。

## 互換性

- **REQ-0224**: V0.1の形式バージョンは `1` とする。
- **REQ-0225**: V0.1では形式バージョンを表示するだけで、値による解析分岐や自動移行を行わない。
- **REQ-0227**: 未知の正の整数バージョンは表示する。V0.1の解析規則を適用し、発生した構造上の問題を通常の診断として表示する。

## 形式変更の運用（要求IDなし）

この節は現在の入力形式の検証対象ではなく、形式を変更するときの運用ルールを示すため、要求IDを付けない。

互換性を壊す変更を行う場合は形式バージョンを増やし、ADRで移行方針を決定する。
