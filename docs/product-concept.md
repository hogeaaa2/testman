# 製品コンセプト

## 位置づけ

`testman`は、Gitで管理しやすいテスト仕様と、日々蓄積される実施結果を分離する。

```text
テスト仕様ファイル（Git管理）
        ↓ 読み込み・検証
testman Webアプリ
        ↓ 閲覧・結果入力
SQLite（Git管理しない）
```

仕様ファイルはレビュー、履歴比較、ブランチ運用に向く。一方、実施結果は頻繁に増えるためDBへ保存する。この分離により、テスト設計の変更履歴と実施履歴をそれぞれ適切な方法で扱う。

## 基本的な利用フロー

1. テスト設計者が仕様ファイルを編集する。
2. Gitで変更をレビューし、利用環境へ配置する。
3. `testman`を起動し、仕様を読み込む。
4. テスト実施者がブラウザで対象テストを選ぶ。
5. 手順と期待結果を見ながらテストする。
6. PassまたはFailと必要なコメントを入力する。
7. 後から同じテストの履歴を確認する。

## 設計原則

- 仕様ファイルがテスト内容のSource of Truthである。
- Web UIは仕様を読みやすく表示し、結果入力を支援する。
- Web UIから仕様ファイルそのものは編集しない。
- DBは実施記録のSource of Truthである。
- 仕様と結果を暗黙に同期・削除しない。
- V0.1ではローカルまたは信頼できる閉じた環境での単独利用を優先する。

## 最初の縦切り実装

V0.1全体を一度に作らず、次の一連の動作を最初に成立させる。

```text
サンプル仕様を1ファイル読み込む
  → 一覧を表示する
  → 1件の詳細を表示する
  → Pass / Failとコメントを登録する
  → 履歴を表示する
```

この縦切りで、仕様形式、画面構成、DBとの対応関係が妥当かを評価する。
